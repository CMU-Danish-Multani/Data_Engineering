The project in brief

We are building a dashboard that compares 5 AI infrastructure companies: Microsoft, Alphabet, Amazon, Meta and NVIDIA. It tracks 13 KPIs (key performance indicators) in three groups: 7 financial, 3 valuation and 3 product metrics. It also shows how big investment funds change their holdings. All data is public, from the SEC (the U.S. regulator that holds company filings) and Yahoo Finance. It covers fiscal years 2019 to 2025, which is 140 company quarters.

The problem

Company results are spread across filings, press releases and price data. Each source uses its own format, and the companies end their fiscal years in different months. An investor has to collect and line up these numbers by hand. Our pipeline does this once, and every number links back to the filing it came from.

Where the data lives, and how raw and clean are kept apart

  • Shared cloud: PostgreSQL on AWS RDS and MongoDB Atlas, used by the whole team. The data is real and large (13,540,608 13F rows scanned), and its messiness is kept, not cleaned before loading.
  • Raw: stored exactly as received, with no keys or type rules that could reject a row. MongoDB keeps the original documents. PostgreSQL keeps raw text rows (dev.raw_stock_prices, dev.f13_infotable) and the original ZIP files. Bad rows are flagged, never deleted.
  • Clean: tables in the dev schema with proper types, keys and checks (for example dev.quarterly_revenue).
  • Final: views in the final schema. The dashboard reads only these.

2. HOW WE TRANSFORM THE DATA, AND WHAT WAS HARD

Transformation steps

  • Find the quarters. We use each company's real quarter dates, because Microsoft's year ends in June and NVIDIA's in late January.
  • Turn year-to-date totals into quarters. Cash flow is reported year to date, so each quarter = this total minus the last one.
  • Adjust for stock splits. Per-share numbers are restated for splits (NVIDIA 4:1 and 10:1, Amazon and Alphabet 20:1).
  • Read product numbers from each press release, and keep the exact sentence or table row each number came from.
  • Calculate the KPIs in SQL views: growth, margins, free cash flow, P/E, EV/Revenue and FCF yield.

Each load runs as one transaction. Running the cash flow and product loads a second time changed nothing.

Types, missing values and duplicates

  • Types: raw values stay as text so no row is lost; clean tables store dates, whole dollars and exact decimals so math is exact.
  • Missing values: stored as empty (NULL) with a reason, not as zero, because zero would distort averages. The one exception: a filing with no debt line is stored as 0 and labelled.
  • Duplicates: removed using keys (company and exact dates) and file fingerprints, so each quarter is counted once.

Check: Microsoft FY2025 Q4 from its filings gives revenue $76.441 billion, CapEx $17.079 billion and free cash flow $25.568 billion. Our final view shows the same numbers.

Challenges

  • Different fiscal year ends, so quarters are matched on exact dates.
  • Companies label the same number differently, and Alphabet and Meta have several share classes.
  • Product definitions change over time, so growth is only computed when the definition is the same.
  • 13F files mix quarters; we now have 3 full quarter-to-quarter comparisons for 2025.

Next build 2: a vector database on SEC text

  • Split the 143 stored press releases into short passages.
  • Turn each passage into a vector (a list of numbers that captures its meaning) and index it with MongoDB Atlas Vector Search.
  • Then a question like "what did management say about AI demand?" finds the right passages, with links. This answers the second part of Q3. Later, an assistant can answer questions using both the numbers and the text.
